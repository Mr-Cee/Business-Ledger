# Business Ledger development

- Java Swing desktop application, PostgreSQL 17, Java source target 21.
- Release version is `pom.xml`; build metadata is generated by `Release.Common.ps1`. Keep `CHANGELOG.md` current.
- For the existing portable executable, run `Update-Executable.ps1`. Never overwrite a JAR that a running application may still be loading. The updater retains prior JARs and changes the launch configuration for the next run.
- Build new installed releases with `Build-Installer.ps1`; installer application files are versioned and ledger data stays separate. In restricted environments, `-UseExistingRuntime` packages the bundled runtime with a version-stamped bridge to the native Java host. Verify the built launcher.
- Do not package `.local`, databases, backups, credentials, personal CSVs, or test fixtures into the installer. Include only application files, private Java/PostgreSQL runtimes, runtime dependencies, and vendor notices. Never copy PostgreSQL's `data` folder.
- Use disposable test databases on port 55439. Never run destructive tests or stop PostgreSQL against the real ledger cluster on port 55432. Preserve login catalog and all profile databases.
- Multi-cluster startup tests may use 55440–55540 only with fresh clusters under target; stop them by their exact test data paths, never by port or a broad process-name kill.
- Installer `/verify` mode is safe for payload checks without installing. Do not run a real installer or uninstaller on the user's environment merely for validation. Use a disposable Windows user/VM for full installation lifecycle checks.
- `RELEASING.md` documents build, compatibility, data paths, and distribution limitations.
